MSAI SENSING NODE 0.1.0-bench -- 2026-10-13

VERIFIED
- Native ESP-IDF 5.5.5 ESP32-S3 project compiles and links successfully.
- Seven codec tests pass, including actual firmware C++ code built as a host DLL:
  full signed 24-bit range, noise, tones, silence, dimensions, malformed streams,
  CRC and 64-bit sample indices. Reconstruction is sample-for-sample exact.
- Four receiver tests pass: real localhost TLS handshake, valid/invalid token,
  exact recording/decoding, sequence gaps, corruption, malformed status payload,
  CSV export/no-overwrite, BLE AES-GCM tampering and authentication binding.
- Setup UI rendered in the browser with mocked status/scan data; Wi-Fi scan
  selection, Ethernet/local/cloud fields, BLE local-only fields and rates checked.
- Physical board 38F5F090A994 detected on COM17 and flashed with official esptool.
  Bootloader, partition table, OTA data and application verified by flash hashes.
- Existing NVS/calibration region backed up before flashing and excluded from
  flash writes. New setup settings use separate NVS namespaces.
- Physical boot succeeds: ESP32-S3 revision 0.2, 8 MB flash, 8 MB PSRAM, 240 MHz.
- Firmware version 0.1.0-bench runs; setup AP/DHCP and HTTP/mDNS services start.
- USB status command tested: configured=0 receiver=0 running=0 fault=0,
  selectors=0 (CR/30 A), feedback=0 (all relays released).

NOT YET VERIFIED ON THIS NATIVE FIRMWARE
- First-boot portal, DNS/captive popup and save/reboot from a physical client.
- Ethernet DHCP and compressed 10 kSPS acquisition: board currently has no
  Ethernet cable connected (confirmed by the operator). Live network and
  acquisition tests were explicitly deferred by the operator until later.
- Wi-Fi association and sustained compressed 10 kSPS transfer.
- BLE discovery, authentication, negotiated MTU and sustained 1/2/10 kSPS transfer
  against real Windows/Linux adapters. Host crypto tests are not a BLE radio test.
- ADC initialization/timing and migrated relay interlocks under acquisition.
- Reconnect, BOOT/reset recovery and settings persistence through power cycling.
- Long-run throughput, induced outage/overflow and end-to-end zero-gap waveform.
- Calibrated accuracy with known current/voltage references and SCT013-030.

The earlier relay diagnostic firmware passed all four selector combinations on
this board. The earlier Ethernet firmware streamed over the Internet, with drops
reported in one test. Those results do not qualify this new implementation.

Connect PCB Ethernet and laptop to the same DHCP router. Open the board IP or
http://msai-90A994.local/. Create a receiver identity, start the receiver, enter
the setup code, choose Ethernet/local and import its connection.json. Keep sensor
